Connection failed or partner not found

Fix Veyndesk connection problems: partner not found, wrong password, could not open a direct connection, or relay not available.

Last updated 21 October 2026 · Veyndesk 0.5.0

Check the basics

  1. Veyndesk is open on both computers and the status says Ready (green dot).
  2. Both run the same version, ideally the latest. The version is in the window title.
  3. The ID is right (9 digits) and you used the current password. A new one-time password is made every time the app starts.

Messages and what they mean

MessageWhat to do
Wrong passwordAsk for the current password. Passwords are case-sensitive.
Too many wrong passwords. Try again in a few minutes.8 wrong attempts in 5 minutes. Wait about 5 minutes.
No one accepted the connection.The other person didn't click Accept within ~45 seconds. Try again while they watch the screen.
Could not open a direct connection (the network blocks it).Direct P2P failed and no relay was available. See below.
Remote access is disabled on this device.The other computer has no password enabled. They should open Veyndesk normally (a one-time password is shown) or set one in Settings.

Different networks (home, office, mobile data)

Veyndesk first tries a direct connection, then a relay that the shared computer opens through Cloudflare. If both fail:

  • Wait 30–60 seconds after starting Veyndesk on the shared computer, so the relay has time to start (it downloads cloudflared the first time).
  • Firewall / company network: the shared computer needs outbound HTTPS to ntfy.sh, github.com (first start) and Cloudflare. Strict corporate firewalls or DNS filters may block these.
  • Antivirus may block cloudflared. Allow it, or place a trusted copy of cloudflared next to Veyndesk.
  • Windows: allow Veyndesk in Windows Firewall (the installer does this; the portable version asks).
  • Try a different network (for example a phone hotspot) to find out which side is blocking.

Same network

  • Try typing the other computer's IP address instead of the ID.
  • Discovery uses UDP port 21119. Guest Wi-Fi and some routers ("AP isolation") block devices from seeing each other.

Still stuck?

Open an issue with both operating systems, the Veyndesk version, the exact message, and whether the computers are on the same network. Don't post your password.
